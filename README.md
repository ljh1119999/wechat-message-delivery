# wechat-message-delivery

**你的 AI 助手喺微信上发消息，唔好再「发到一半冇声」**

你嘅 AI 助手（Hermes/任何 agent）每日通过微信/企业微信同你汇报铝价、报错、任务进度——但系你系咪经历过：

- 🔇 连续发几条消息之后就**冇下文**，任务做完咗都唔知？
- 🖼️ 发 12 张图你只收到 6 张，日志话「已发送」但系你手边冇？
- 📢 后台任务完成时刷屏一堆**乱码 error**，睇唔明又心烦？
- 🌙 凌晨嘅定时报告悄悄失败，第二日你先发现？
- 🔁 日日收「限流」报错，但系明明你乜嘢都冇做？

呢个 skill 就系把呢啲问题**一个一个实测干掉**嘅完整机制，全部经过 2026-08 真实生产环境踩坑验证：

## 核心原则

> **正常唔打扰，异常必通知，通知只一行。**

## 包含嘅机制

| 问题 | 机制 |
|------|------|
| 连续发消息后中断 | 限流熔断调优（5次真限流先开闸，只锁10秒）+ 发送节奏（文字/图片/文件 1.5s/条） |
| 图片静默丢图 | zip 全量兜底 + 分批发（≤6张/批）+ 缺边张补边张 |
| 后台任务乱码刷屏 | 原始输出入日志，微信只收一行「人话」状态 |
| 定时任务悄悄失败 | 补发脚本自动重发 + 日报列今日 cron 执行情况，失败当晚解决 |
| 定时同步空转 | hash 变更检测，无变化零消息 |
| agent 回合中断 | 每 3-4 步报一次进度、长等待拆短轮询、断咗先讲进度 |
| 代理掉线影响推送 | 独立 systemd 托管 + 节点前预检 + 拉起失败自动降级备用模型 |

## 适用场景

- 用 Hermes / OpenClaw / 自建 agent 通过 **iLink / 企业微信 / 个人微信机器人** 推送嘅用户
- 每日定时报告（铝价、股票、天气、监控）经常「唔声唔声」失败嘅人
- 批量发图/发文件畀客户/同事经常漏图嘅人
- 被「限流」「冇下文」「乱码通知」烦咗好耐嘅人
